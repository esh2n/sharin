# trace-sampling

分散トレーシングのサンプリング戦略。LLM のトークンサンプリングは
別パーツ([llm-sampling](../llm-sampling/))で扱う。

## 肝

- 全トレースは保存できない。問題は「何を残すか」の決め方
- head-based は開始時に確率で決める。安くて伝播も簡単だが、**エラーになるかをまだ知らない**
  ので、低レートではエラートレースもレート通りにしか残らない
- tail-based は完結を見てから決めるのでエラー捕捉率100%にできるが、
  判定できるまで**全 span をバッファする**代償を払う

## 簡略化したこと

- トレースを「完結済みの要約(Duration, Err)」に縮約。span の木や複数サービス間の
  コンテキスト伝播は実装していない
- tail のバッファそのもの(未完トレースの保持、タイムアウト、traceID ルーティング)は
  実装せず、「完結後に中身が見える」という結果だけをモデル化
- レート制御付きサンプリング(X-Ray の reservoir 等)や適応レートは扱わない
