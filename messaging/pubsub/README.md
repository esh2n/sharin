# pubsub — トピック型 Pub/Sub

「1メッセージを購読者**全員**に配る」ファンアウト(one-to-many)。[queue](../queue/) が
点対点(1件を1人が取る)だったのに対し、こちらは一斉配信。

## 肝

- **ファンアウト**: 発行は1回。トピックの購読者は**それぞれ独立に全メッセージ**を読む。
  1件を奪い合うキューとは配り方が逆
- **独立カーソル**: 購読者ごとに「どこまで読んだか」を持つ。遅い購読者がいても、
  他の購読者は止まらない(各自のペースで進む)
- **購読開始位置**: `FromBeginning` は先頭から再生(過去も届く=durable)、`FromNow` は
  購読以降だけ(ephemeral)。「新規購読者は過去を見るか」の設計軸

## 作ったもの

| 型・関数 | 役割 |
|---|---|
| `Broker` / `Publish(topic, body)` | トピック別の追記ログに1件追記 |
| `StartAt` (`FromBeginning`/`FromNow`) | 購読開始位置 |
| `Subscribe(topic, start)` | 購読を作る(自分のカーソルを持つ) |
| `Subscription.Poll(max)` | 未読を取り、カーソルを進める |
| `Backlog` / `Cursor` / `Len` / `NumTopics` | 観測用 |

goroutine やネットワークは使わない純粋なモデル。100% カバレッジ・`-race` クリーン。

## queue との違い

| | queue(点対点) | pubsub(ファンアウト) |
|---|---|---|
| 1メッセージの受け手 | 1人(奪い合う) | 購読者全員 |
| 主な用途 | ジョブ分配・負荷分散 | イベント通知・ブロードキャスト |
| 実物 | SQS、RabbitMQ ワークキュー | Redis Pub/Sub、SNS、MQTT、Kafka の複数コンシューマグループ |

Kafka は両方を1つで表す——同じグループ内は点対点(分担)、グループを分ければファンアウト。

## 簡略化したこと

- ワイルドカード購読(MQTT の `sensor/+/temp` など階層トピック)は無し。トピックは完全一致
- バックプレッシャ・保持期限・遅い購読者の drop ポリシーは無し(ログは伸び続ける)
- ネットワーク・永続化は無し(全てメモリ)。配送保証(冪等・再送)は [queue](../queue/) 側の話
- 購読解除(unsubscribe)やトピック削除は扱わない
