# queue — ログ型メッセージキュー

Kafka のように、メッセージを追記専用の**ログ**に積み、消費者は自分の**オフセット**で読む。
配送保証(delivery semantics)の違いを、クラッシュを起こしながら目で見えるようにする。

## 肝

- **ログ + オフセット**: ブローカはメッセージを消さない。消費者が「どこまで読んだか」の
  オフセットを進めるだけ。だから複数の消費者が独立に、同じログを好きな位置から読める
- **配送保証**: 確定(オフセット更新)と処理のどちらを先にやるかで決まる
  - `AtMostOnce`(確定→処理): 処理前に落ちると**取りこぼす**(重複なし)
  - `AtLeastOnce`(処理→確定): 確定前に落ちると**再配送=重複**(取りこぼしなし)
- **実質1回(effectively-once)**: `AtLeastOnce` + **冪等な消費者**。メッセージのキーで
  重複を捨てれば、再配送されても副作用は1回きり。分散では「取りこぼさない」と「重複しない」の
  完全両立は難しく、実務はここに寄せる

## 作ったもの

| 型・関数 | 役割 |
|---|---|
| `Broker` / `Publish` / `Len` | 追記専用ログ。メッセージは消えない |
| `Semantics` (`AtMostOnce`/`AtLeastOnce`) | 配送保証 |
| `Consumer` / `Poll(max)` | オフセットで読み、保証に従って処理 |
| `Consumer.PollCrash(max)` | 「オフセット確定の前後で中断した」クラッシュを模す |
| `IdempotentSink` / `Handle` | Key で重複を捨てる冪等な受け皿(実質1回) |

goroutine やネットワークは使わない純粋なモデル。クラッシュ(確定前の中断)も決定的に再現できる。

## 簡略化したこと

- 1パーティション・1ログのみ。パーティション分割/コンシューマグループは無し
  (キーで分割 → 各パーティションを [consistent-hashing](../../distributed/consistenthash/) で
  ノードに割る、が実物の形)
- 永続化・ネットワーク・保持期限(retention)は無し(ログはメモリ、消えない)
- 冪等は「Key を覚える」だけ。実務は処理結果側の UNIQUE 制約や処理済み表で担保する
- 順序保証は1ログ内のみ。複数パーティション間の全順序は扱わない
