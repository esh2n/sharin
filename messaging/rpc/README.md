# rpc — 最小の遠隔手続き呼び出し

「関数を呼ぶように、別プロセスの処理を呼ぶ」RPC を、シリアライズ・フレーミング・相関から
自作する。gRPC/protobuf 風の最小版。

## 肝

- **シリアライズ**: 型のある要求/応答をバイト列にして戻す。protobuf 風に
  [フィールド番号][値] を並べ、整数は varint(小さいほど短い)、文字列は [長さ][中身]
- **フレーミング**: バイトストリームには境界が無い。長さを前置きして「1メッセージ」を切り出す。
  これをしないと2つの送信がくっつく/途中で切れる(TCP はバイトの列で、メッセージの列ではない)
- **相関(correlation)**: 1本の接続に要求を多重化し、応答を**要求IDで突き合わせる**。
  サーバは並行に処理するので、応答は送った順に返るとは限らない
- **RPC はローカル呼び出しではない**: ネットワークエラー・タイムアウト・部分故障が起きる。
  再送は処理を二重に走らせうるので、受け手は冪等であるべき(→ [message-queue](../queue/))

## 作ったもの

| 型・関数 | 役割 |
|---|---|
| `writeFrame`/`readFrame` | 長さ前置きのフレーミング |
| `Call`/`Reply` + `encode/decode` | protobuf 風のシリアライズ |
| `Server` / `Register` / `Serve(conn)` | メソッド登録、要求を並行処理し応答 |
| `Client` / `Call(ctx, method, body)` | 多重化して呼び、ID で相関、ctx でタイムアウト |
| `RemoteError` | サーバ側エラーを呼び出し側へ運ぶ |

`net.Pipe` などの `net.Conn` 上で動く。応答読み取りは goroutine、書き込みは直列化。
`go test -race` でクリーン(並行相関を検証)。

## 簡略化したこと

- スキーマ(.proto)もコード生成も無し。Body は生バイト列で、各メソッドが自分で解釈する
- 1接続のみ。コネクションプール・ロードバランシング・再接続は無し
- 再送(retry)・サーキットブレーカ・デッドライン伝播は入れていない(呼び出し側の ctx 打ち切りまで)。
  実務はここに冪等 + 再送 + バックオフを重ねる
- ストリーミング RPC(双方向の連続メッセージ)は扱わない。1要求1応答のみ
