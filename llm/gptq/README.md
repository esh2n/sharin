# gptq — 丸めた誤差を、まだ丸めていない重みへ配る

[quant](../quant/) では最寄りの格子点に丸めて、出た誤差はそのまま捨てた。

だが層の出力は内積になる。`y = Σ wᵢxᵢ` なので、効いてくるのは重み1つずつのずれではなく、
**入力を掛けて足し合わせたあとのずれ**だ。個々の丸めが半格子以内でも、同じ向きに揃えば積み上がる。

## 小さくしたいのは出力のずれ

64次元、共通成分の強い入力を256回ぶん、3bit:

```
                重みのずれ    出力のずれ
  素朴な丸め      0.08682       0.32736
  誤差を配る      0.09272       0.04069   ← 1/8
```

**重みのずれは増えているのに、出力のずれは 8 分の 1 になっている。**
最寄りに丸めるのをやめたのだから、重みが離れるのは当然。それを承知で離す。

## 配る先は入力の相関が決める

```go
plan := gptq.Plan(x, 0.01)              // H⁻¹ のコレスキー分解
fix := gptq.Quantize(w, plan, 3)        // 前から順に確定させ、残りへ配る
rtn := gptq.RoundToNearest(w, 3)        // 対照
```

得の大きさは、入力どうしがどれくらい一緒に動くかでそのまま決まる(3bit):

| 入力の共通成分 | 素朴な丸め | 誤差を配る | 比 |
|---|---|---|---|
| 0.0 | 0.37310 | 0.37350 | 1.00 |
| 0.5 | 0.25517 | 0.18892 | 1.35 |
| 0.7 | 0.27364 | 0.11339 | 2.41 |
| 0.9 | 0.32736 | 0.04069 | 8.05 |
| 0.95 | 0.34461 | 0.02488 | 13.85 |

相関がまったく無ければ得も無い。ヘッセ行列の非対角を落として対角だけにすると、
配る先が消えて **素朴な丸めと1ビットも違わない結果** になる(テストで固定)。

## 分解1回で全段ぶんが手に入る

1つ確定させるたびに「残った重みについてのヘッセ行列」を作り直すのが理屈だが、
`H⁻¹` を `Uᵀ U` に分解しておくと、**上三角 `U` の `i` 行目がそのまま `i` 段目の配り方** になる。
削っていく操作が分解の中に入っているので、重みを前から1回なぞるだけで済む。

ここが GPTQ が OBQ から進んだところで、数万次元の層が現実的な時間で量子化できる理由になる。

## API

| 関数 | 役割 |
|---|---|
| `Hessian(x, damp)` | `H = X Xᵀ / n`、対角に下駄を履かせる |
| `Diagonal(h)` | 非対角を落とす(相関を無視した対照) |
| `Inverse(a)` | 掃き出し法 |
| `CholeskyUpper(a)` | `A = Uᵀ U` の上三角 |
| `Plan(x, damp)` | 上を通して配り方を作る |
| `Quantize(w, plan, bits)` | 順に確定させ、残りへ配る |
| `RoundToNearest(w, bits)` | 対照 |
| `OutputError(w, q, x)` / `WeightError(w, q)` | 2つのずれ |

## 決定性

実時間も乱数も使わない。入力は整数の線形合同法から作るので、同じ手順なら必ず同じ結果になる。
