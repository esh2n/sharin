# prune — どれを 0 にするか

[gptq](../gptq/) では丸め先を選ぶのに入力の相関を使った。同じ道具で別の問いにも答えられる。
もともと順序は逆で、この枠組みは **枝刈りのために** 考えられたものだった(OBS、1992年)。

## 大きさで選ぶのは近似でしかない

```
  入力の振れ方        重み       出力への寄与       絶対値で選ぶと
  大きく振れる        0.01       それなりに動く     消される ✗
  ほとんど動かない    0.90       ほとんど動かない   残される ✗
```

消す損の見積もり:

```
  L_i = w_i² / (2 · [H⁻¹]_ii)
         ▲            ▲
         │            └ 補いやすさ。残りで肩代わりできるほど大きい
         └ 重みの大きさ
```

対角だけに制限すると `[H⁻¹]_ii = 1/H_ii` なので `L_i = w_i² H_ii / 2` になり、
**OBD(1989)の見積もりと一致する**(テストで固定)。振れ幅が揃っていれば絶対値の順そのもの。

## 選び方と補い方は対になっている

64次元、32個(50%)を消したときの出力のずれ:

| 入力の共通成分 | 大きさで選ぶ | 効きで選ぶ(補正なし) | 効きで選んで補う |
|---|---|---|---|
| 0.0 | 0.18986 | 0.06705 | 0.06980 |
| 0.3 | 0.13782 | 0.05074 | 0.04953 |
| 0.7 | 0.09929 | 0.11379 | **0.02658** |
| 0.9 | 0.10545 | **0.19033** | **0.01696** |

見積もりの分母は「補えるなら安い」と言っている。つまり **補うことを前提にした値段**。
だから補わずにこれで選ぶと、相関が強いところでは素朴な選び方より悪くなる(0.10545 → 0.19033)。

さらに、共通成分 0.9 では **選ぶ位置そのものは 64 か所中 4 か所しか変わらない**。
差の出どころは選び方ではなく、補うかどうかだけになる。

## 消すたびに残りを動かし、見積もりも作り直す

```go
hinv := prune.Plan(x, 0.01)
obs := prune.BySaliency(w, hinv, 32)   // 毎回いちばん安いものを選び直す
```

量子化と違って消す順は固定ではない。そして 1 つ消すたびに `H⁻¹` を作り直す
(掛け算と引き算だけで済むので、逆行列は取り直さない)。

補正の得は入力の相関がそのまま決める:
共通成分 0.0 で 2.72倍、0.3 で 2.78倍、0.7 で 3.74倍、0.9 で 6.22倍。

## API

| 関数 | 役割 |
|---|---|
| `Saliency(w, hinv)` | 消す損の見積もり |
| `ByMagnitude(w, k)` | 絶対値の小さい順に k 個(補正なし) |
| `BySaliencyOnly(w, hinv, k)` | 効きの小さい順に k 個(補正なし。切り分け用) |
| `BySaliency(w, hinv, k)` | 効きで選び、消すたびに残りを動かす(OBS) |
| `Plan(x, damp)` | `H⁻¹`。gptq の道具をそのまま使う |
| `Kept(w)` / `OutputError(w, p, x)` | 残った数 / 出力のずれ |
