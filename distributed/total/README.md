# total — 全員が同じ順で受け取る

[causal](../causal/) では並行なものに順序を付けなかった。付けないから誰も待たずに済み、
切れても止まらない。

だが、それが通らない場面がある。残高 1000 円に 800 円と 500 円の引き落としが並行に届いたら、
どちらか片方は拒否されなければならない。**どちらの順でもよいが、全員が同じ順でなければならない。**

## 作り方は2つ

### 番号を振る係を置く

```go
s := total.NewSequencer("a", "b", "c")
m1 := s.Assign("a", "1")   // 係に届いた順に番号が付く
s.Deliver("b", m1)         // 受け取る側は番号順にしか渡さない
```

速い。だが係が止まれば全員が止まり、番号に穴が空くだけでも後ろが全部止まる。

### 全員で決める

```go
s := total.NewVoting("a", "b", "c")
x := s.Request("a", "A")   // 時刻 1
y := s.Request("c", "C")   // 時刻 1(同時刻は名前で決まるので a が先)
// 渡す条件: 先頭より後の時刻を、他の全員から聞いていること
s.Beat("b")                // 要求が無くても時刻を知らせる必要がある
```

係は要らない。だが**過半数ではなく全員**から聞くので、1台が黙るだけで全体が止まる。

## 全員が同じ順で間違えることがある

```go
s := total.NewSequencer("a", "b", "c")
s.Assign("b", "回答")   // 係には回答のほうが先に届いた → 番号 1
s.Assign("a", "質問")   // → 番号 2
// 3台とも 回答 → 質問。完全に一致していて、答えが問いより先に来ている
```

**順がそろうことと、順が正しいことは別の性質になる。** 全順序にすれば因果順も付いてくる、
というのは成り立たない。両方が要るなら両方を用意する(ISIS が CBCAST と ABCAST を
分けて提供していたのはこのため)。

## 待つ相手が居るから止まる

```
                待つ相手      1台切れたら
  因果順序      居ない        止まらない
  全順序(係)   係            係が落ちれば全員止まる
  全順序(全員) 全員          誰が落ちても全員止まる
  全順序(合意) 過半数        少数が落ちても続く
```

[raft](../raft/) は、待つ相手を**全員から過半数へ**落とす仕組みになる。
全順序放送と合意が同じ強さだと言われるのは、この意味になる。

## API

| 関数・メソッド | 役割 |
|---|---|
| `NewSequencer(names...) *SeqSim` | 係を置く方式 |
| `(*SeqSim) Assign(from, body) Numbered` | 係に届いた順に番号を付ける |
| `(*SeqSim) Deliver(to, m) []Numbered` | 番号順に渡す。穴があれば預かる |
| `NewVoting(names...) *VoteSim` | 全員で決める方式 |
| `(*VoteSim) Request(from, body) Msg` | 時刻つきで要求を出す |
| `(*VoteSim) Beat(from) Msg` | 時刻だけを知らせる |
| `(*VoteSim) Deliver(to, m) []Msg` | 条件がそろったものを渡す |
| `(*VoteNode) Queue() []Msg` | 待ち行列(決まった順) |
| `(*VoteNode) Heard() map[string]int` | 各台から最後に聞いた時刻 |
| `Agreed(orders...) bool` | 全員が同じ順で渡しているか |

## 決定性

実時間も乱数も使わない。誰にいつ届くかは呼び出し側が明示する。
