# antientropy — 全件送らずに差分を見つける

[quorum](../quorum/) の読み修復には穴がある。**読まれない key はいつまでも古いままになる。**
誰も見ていない値ほど直らない。だから読みとは別に、台どうしを突き合わせる仕組みが要る。

全件送れば確実だが、違いが1件でも持ち物の数だけ通信が出る。

## 木にすると、違う枝だけ降りられる

key を区画に割り振り、区画ごとの要約を葉にして木を組む。根から降りて、
一致したところで打ち切る。

```
区画 1024(高さ 10)、1000 件、そのうち 1 件だけ違う

  全件で比べる   比較 1000   送信 1000
  木で降りる     比較   21   送信    1     ← 1 + 2×10
```

比べる数は **持ち物の数ではなく、違いの数と木の高さ** で決まる。

```
件数を変えても比較は変わらない(区画は 1024 のまま)

    1000 件 → 比較 21  送信  1
   10000 件 → 比較 21  送信  8
  100000 件 → 比較 21  送信 95   ← 1 区画あたりの件数が増えるから
```

送る量だけは件数に比例するので、**件数が増えたら区画も増やす**。

違いが増えると降りる枝が増え、木の得は減っていく(1000 件・区画 1024):

| 違い | 比較 | 送信 |
|---|---|---|
| 0 | 1 | 0 |
| 1 | 21 | 1 |
| 16 | 201 | 21 |
| 64 | 561 | 92 |

**ほとんど同じ相手ほど得が大きい。** こまめに回して差を溜めないほうがよい。

## 木は在処までしか言わない

```go
a, b := antientropy.NewStore(1024), antientropy.NewStore(1024)
a.Put("k", "古い", 1)
b.Put("k", "新しい", 2)
antientropy.Sync(a, b)   // 木は「この区画が違う」まで
                          // どちらが新しいかは quorum.Newer が決める
```

見つける仕組みと決める仕組みは別々に要る。
[gossip](../gossip/) で「返事が無い」が死か断線かを言わなかったのと同じ形になる。

また、**区画の切り方が両側で同じでなければ比べようがない**。
台を増やして担当範囲が変わると、木を作り直すことになる(Dynamo 論文が弱点として挙げている点)。

## API

| 関数・メソッド | 役割 |
|---|---|
| `NewStore(buckets) *Store` | 区画の数を決めて台を作る |
| `(*Store) Put(key, data, stamp)` | 版番号が古ければ何もしない |
| `(*Store) Tree() *Tree` | 要約の木を組む |
| `(*Tree) Root() / Depth()` | 全体の要約 / 高さ |
| `Diff(a, b *Tree) ([]int, int)` | 違う区画と、比べた数 |
| `Sync(a, b *Store) Result` | 木で探して、違った区画だけ交換する |
| `CompareAll(a, b *Store) Result` | 木を使わず全件(対照用) |

## 決定性

実時間も乱数も使わない。区画の中は名前順に混ぜるので、置いた順が違っても同じ要約になる。
