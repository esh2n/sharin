# dlock — 分散ロックとフェンシングトークン

複数ノードで 1 つの資源を排他する——**分散ロック**の核心と、その正しさを支える
**フェンシングトークン**を Go でモデル化する。分散システム編のパーツ。

教科書の章: [distributed-lock](https://sharin-2a1.pages.dev/parts/distributed-lock)

## これは何か

1 台のマシンなら `mutex` で排他できる。だが複数ノードにまたがると、途端に難しくなる。
理由はただ 1 つ——**ロックを持ったノードはいつでもクラッシュしうる**。持ったまま
死なれたら、ロックは永遠に解放されない。

そこで分散ロックは、ロックに**リース(有効期限)**を付ける。一定時間で自動失効させ、
持ち主が死んでも他が取れるようにする。だがリースは新たな罠を生む:

- 持ち主が死んでいなくても、**GC の一時停止・ネットワーク遅延**で「まだ持っている
  つもり」のまま時間だけ過ぎることがある
- その間にリースが失効し、別ノードが同じロックを取る = **二重取得**
- 出遅れた古い持ち主が resource に書き込むと、新しい持ち主の仕事を**破壊**する

この破壊を防ぐのが**フェンシングトークン**。ロックを与えるたびに単調増加する番号を
発行し、resource は「今まで見た最大の番号より小さい書き込みを拒む」。古い持ち主の
書き込みは番号が古いので弾かれる——これが分散ロックを本当に安全にする鍵だ。

```
   A がロック取得(token=1) ──write(1,"A")──▶ resource(max=1) "A"
   A が GC 停止… その間にリース失効
   B がロック取得(token=2) ──write(2,"B")──▶ resource(max=2) "B"
   A 再開、まだ持ってるつもりで書く ──write(1,"STALE")──✗ 1<2 で拒否
                                                        └ 破壊されない
```

## 肝は3つ

1. **リース = 失効するロック**: 持ち主のクラッシュに耐えるため、ロックは時間で自動失効する
2. **失効の罠 = 二重取得**: GC 停止や遅延で「持っているつもり」の古い持ち主と、新しい
   持ち主が同時に存在しうる
3. **フェンシングトークン = 単調増加番号**: 資源側が古い番号の書き込みを弾く。これで
   二重取得が起きても破壊を防げる

## ファイル

- `lock.go` — `LockService`。論理時計・リース(失効)・単調増加トークンの発行。
  `Acquire` / `Renew`(ハートビート) / `Release` / `Holder`
- `resource.go` — `Resource`。フェンシング付きの `Write`(token が最大以上なら受理、
  古ければ拒否)。比較用に `NewUnfencedResource`(フェンス無し=破壊が起きる)も用意

## 設計メモ

- **合意は前提として省く**: 「1 本のロックを誰に貸すか」の合意そのものは、実際は Raft や
  Zookeeper/etcd の上に載る。ここではその合意は取れている前提で、**リースとトークンの
  意味論**だけを取り出す
- **トークンは取得のたびに増える**: `Renew` では変わらない(同じ保持の延長だから)。
  `Acquire` のたびに `nextToken++`。だから「新しく取り直した持ち主」を番号で見分けられる
- **フェンシングは受理側で効く**: 鍵は resource が `token >= maxToken` を検査すること。
  ロックサービスがいくら頑張っても、資源側がトークンを見なければ二重書き込みは防げない
- **決定的**: 実時間ではなく論理時計。`Tick(d)` で時間を進めるので、失効と再取得の
  タイミングを毎回同じに再現できる

## 簡略化したこと

- **合意層は無し**: ロックの一意性を保証する合意(Raft/Paxos)は前提。単一の `LockService`
  が真実を持つ(実際はここが分散合意になる)
- **クロックは論理時計**: 実時計・クロックスキュー・NTP ずれは扱わない(Redlock 論争の
  時計依存性は章で説明)
- **1 本のロックのみ**: 複数ロック・デッドロック検出・公平性(待ち行列)は扱わない
- **ネットワーク故障を明示モデル化しない**: 遅延・停止は `Tick` で時間を進めることで表す
