# gossip — 誰に届けるか、そして誰が死んだか

[crdt](../crdt/) の章で、後からまとめられる形を作った。だがそこには、
**そもそも誰に届けるのか**が無かった。

全員が全員を見張ると、通信は台数の2乗になる。100台なら1万通り。
ゴシップの答えは、**毎周期ランダムに1台だけ選んで話しかける**ことになる。
1台が出す通信は台数に関係なく一定で、それでも知らせは全体に広まる。

## 1台では死を判定できない

返事が無いのは、相手が死んだからかもしれないし、自分と相手の間だけが切れているからかもしれない。

```go
s := gossip.New(gossip.Config{Indirect: 2, SuspectFor: 3}, seed, "a", "b", "c", "d", "e")
s.Block("a", "b")   // a から b へだけ届かない。b は生きている
for i := 0; i < 20; i++ { s.Round() }
s.Node("a").View("b").State  // Alive ← 他の台に頼んで確かめた
```

他の何台かに「あなたから話しかけてみて」と頼む。誰か1人でも届いたなら相手は生きている。
`Indirect: 0` にすると区別できなくなり、断線しただけで疑い始める。

## 3つの状態

| State | 意味 |
|---|---|
| `Alive` | 生きていると見ている |
| `Suspect` | 疑わしい。まだ決めていない |
| `Dead` | 死んだと決めた |

即断せず、まず疑いに置く。`SuspectFor` 周期のあいだ本人に反論の機会を残す。
猶予を延ばすと誤検知は減るが、決まるまでが遅くなる。

## 主張できるのは本人だけ

```go
Merge(a, b Member) Member
// ① Inc が大きいほうが勝つ
// ② 同じなら Dead > Suspect > Alive(悪い知らせが勝つ)
```

疑われた本人は `Inc` を1つ上げて「生きている」を広める。番号が大きいので古い疑いを上書きできる。
他人は番号を上げられないので、**勝手に疑いを取り消せない**。

この `Merge` は可換・結合的・冪等なので、[crdt](../crdt/) と同じくどの順で何度届いても同じところへ落ち着く。
`Inc` の単調さは[論理時計](../clock/)の数え上げと同じ役目になる。

## API

| 関数・メソッド | 役割 |
|---|---|
| `New(cfg, seed, names...) *Sim` | seed で選び方を固定する。結果は再現する |
| `(*Sim) Round()` | 全員が1台ずつ問い合わせる |
| `(*Sim) Kill` / `Revive` / `Block` | 落とす・起こす・一方向に切る |
| `(*Sim) Agreed(name) (State, bool)` | 生きている全員の見立てがそろっているか |
| `(*Sim) RunUntilAgreed(name, want, limit) int` | そろうまでの周期数 |
| `(*Sim) Pings` | 問い合わせの総数。台数への依存を見る |
| `Merge(a, b) Member` | 見立てのまとめ方 |

## 決定性

実時間を使わず、相手の選び方は seed から決まる線形合同法で固定する。
同じ seed と同じ操作なら必ず同じ結果になる。
