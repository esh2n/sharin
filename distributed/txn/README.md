# distributed/txn — 分散トランザクション(2PC / Saga)の最小実装

複数サービスにまたがる更新を「全部成功か、全部無かったことにするか」で揃える 2 つの方法を、
決定的な Go でモデル化する。

1. **2 相コミット(2PC)**(`twopc.go`): 調整役が全員に prepare を聞き、全員 Yes のときだけ
   commit を配る。1 人でも No なら全員 abort。「一部だけ引き落とされた」状態は決して確定
   しない。代償はブロッキング——`RunPrepareOnly` が「決定を配る前に調整役が落ちた」を模し、
   Yes と答えた参加者がロックを抱えて動けなくなる様子を見せる。
2. **Saga**(`saga.go`): ロックを持たない。各ステップをローカルに即コミットし、失敗したら
   完了済みステップの補償(打ち消し)を逆順に実行する。止まらないが、途中状態が外から見える。
   補償はロールバックではなく「キャンセル」という新しい操作である点が要。

## 実行

```sh
go test -race -cover ./distributed/txn/
```

`-race`・`go vet` クリーン、カバレッジ 86.2%。2PC の原子性・ブロッキング、Saga の逆順補償・
途中状態の可視性を、それぞれテストで固定している。教科書の該当章は
`docs/parts/distributed-txn.md`。
