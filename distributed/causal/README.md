# causal — 原因の順で配る

[clock](../clock/) の章で、どちらが先かを見分ける道具を作った。だが分かるのは
「見分けられる」ところまでで、それを使って何をするかは別の話になる。

使いどころが配送になる。放送で流したメッセージは、届く順が送った順と違う。
すると、**ある投稿への返信が、その投稿より先に見えてしまう**。

## 送り手ごとの通し番号では直らない

同じ相手からの追い越しは通し番号で直る。だが返信は**別の相手**から来る。
原因と結果が送り手をまたいでいるところが、この問題の要点になる。

```go
s := causal.New(causal.Fifo, "a", "b", "c")
s.Broadcasts("a", "質問", "b")   // c には届いていない
r := s.Broadcasts("b", "回答", "a")
s.Deliver("c", r)                // 渡ってしまう
s.Node("c").Order()              // [回答 質問]
```

## 届いてもすぐには渡さない

メッセージに「流した時点で送り手が見ていたもの」を載せておく。
[ベクタークロック](../clock/)そのものになる。

```go
// 送り手 j からのメッセージ m を、seen まで渡し終えた側で見るとき
// ① m.Deps[j] == seen[j] + 1     この送り手の次の1件であること
// ② m.Deps[k] <= seen[k]  (k≠j)  送り手が見ていたものを自分も見ていること
```

①だけなら送り手ごとの順、②が付くと原因の順になる。**判定に要るのは数の大小だけ**で、
時刻も順序づけも要らない。収まらないものは預かりに置き、収まった瞬間にまとめて渡る。

```go
s := causal.New(causal.Causal, "a", "b", "c")
q := s.Broadcasts("a", "質問", "b")
r := s.Broadcasts("b", "回答", "a")
s.Deliver("c", r)     // 預かる(渡さない)
s.Deliver("c", q)     // 質問と回答がまとめて渡る
s.Node("c").Order()   // [質問 回答]
```

## 決まらないところは決めない

並行なメッセージには順序を付けない。だから台ごとに渡る順が違ってよい。

```go
x := s.Broadcast("a", "犬")   // 互いを見ていない
y := s.Broadcast("c", "猫")
causal.Relation(x, y)         // Concurrent
// b は 犬 → 猫、c は 猫 → 犬。どちらも原因の順は満たしている
```

全員で同じ順にそろえたいなら、それは合意の仕事になる([raft](../raft/))。

## 代償

**原因が来なければ、結果は永遠に渡らない。** 待つ側には、それが遅れなのか
永久に来ないのかを区別する手立てが無い。

## API

| 関数・メソッド | 役割 |
|---|---|
| `New(mode, names...) *Sim` | `Fifo` か `Causal` を選ぶ |
| `(*Sim) Broadcast(from, body) Message` | 流す。出した本人にはその場で渡る |
| `(*Sim) Deliver(to, m) []Message` | 届いたことにする。渡せたものを返す |
| `(*Sim) Broadcasts(from, body, to...)` | 流して、指定した相手にその場で届ける |
| `(*Node) Order() []string` | 渡した順 |
| `(*Node) Held() []Message` | まだ渡せていない預かり |
| `(*Node) Seen() clock.Vector` | 渡し終えた数 |
| `Relation(a, b) clock.Ord` | 2件の前後。並行なら `Concurrent` |

## 決定性

実時間も乱数も使わない。誰にいつ届くかは呼び出し側が明示する。
