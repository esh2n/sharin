# chain/lightning — Lightning Network(決済チャネル)の最小実装

ブロックチェーンに毎回載せずに、2 者が資金を一度ロックして以降の残高更新をオフチェーンで
やり取りする決済チャネルを、決定的な Go でモデル化する。3 本柱:

1. **ステートチャネル**(`channel.go`): funding で一度だけチェーンにロックし、以降 `Pay` は
   commitment(残高割り当て)を差し替えるだけ。チェーンに触れるのは開閉の 2 回きり。
2. **リボケーションとペナルティ**(`penalty.go`): 状態を進めるたびに旧 commitment の
   リボケーション秘密を相手に渡す。古い(自分が有利だった)状態を提出すると、相手が
   その秘密で全額没収できる。だから正直でいるのが最も得になる。
3. **HTLC とマルチホップ**(`htlc.go`): 直接繋がらない相手へ、途中のノードを信頼せず送る。
   受取人だけが知る preimage のハッシュで各ホップをロックし、preimage が下流から上流へ
   伝播して経路全体が同時に成立する。出なければタイムアウトで返る。

## 実行

```sh
go test -race -cover ./chain/lightning/
```

`-race`・`go vet` クリーン、カバレッジ 89.7%。実クリプト・実ネットワークは使わず、
ハッシュと論理時計で仕組みだけを取り出している。教科書の該当章は `docs/parts/lightning.md`。
