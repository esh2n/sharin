# db/btreestore

B-Tree をバッファプールの上に載せた永続インデックス。db 編の第4段。

## 肝

- data-structures/btree はメモリ内の *node ポインタの木だった。ここでは各ノードを
  1ページに直列化し、ポインタの代わりにページIDで参照する
- ページの読み書きは全て bufferpool を通す。根に近いノードは何度も通るので自然と
  キャッシュに残り、実質メモリ木のように速い
- 挿入アルゴリズムはメモリ版とまったく同じ proactive split。違いは「ポインタを辿る」が
  「ページIDを readNode で読む」に、「代入」が「writeNode で書き戻す」に変わるだけ

## 簡略化したこと

- 削除は未実装(メモリ版に揃えた)
- キーも値も uint64 固定。可変長・複合キーは扱わない
- ページ内は素朴な配列(スロット配列や接頭辞圧縮はしない)
- クラッシュ安全性は WAL 未統合。Close でしか確実に永続化しない(次段の宿題)
- 空きページの再利用(フリーリスト)なし。nextID は増える一方
