# db/kvlog (ログ構造KV)

追記だけの KV ストア(Bitcask 型)。db 編の第1段。

## 肝

- ディスクには追記しかしない。上書きも削除も「新しいレコードの追記」で表現する。
  既存バイトを触らないから、クラッシュで壊れうるのは末尾の書きかけだけ
- ディスクは全履歴、メモリのインデックスが「各キーの最新の場所」を知っている
- 再起動 = ログを先頭から再生してインデックスを組み直す。壊れた末尾は切り捨てる。
  これが WAL とイベントソーシングに共通する核

## 簡略化したこと

- チェックサム(CRC)なし。実物は「末尾が切れた」だけでなく「途中が化けた」も検出する
- コンパクション(古いレコードの掃除)なし。ログは伸び続ける
- fsync の制御なし(OS のバッファ任せ)。durability の議論は WAL 編で
- 全キーのインデックスがメモリに載る前提。単一 mutex
