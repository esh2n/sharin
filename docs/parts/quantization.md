# 量子化(int8 / int4)

> 実装: [`llm/quant/`](https://github.com/esh2n/sharin/tree/main/llm/quant) / 実行: `go test ./llm/quant/`

<Summary>
学習済みの重みを fp32 で持つと 70B パラメータで 280GB になり、GPU に載らない。量子化は各重みを int8 や int4 の整数に写し、メモリを 1/4〜1/8 に縮める。値の範囲を整数の格子に写す scale を決めて丸めるだけの仕組みで、丸め誤差と引き換えにメモリを節約する。この章では対称・非対称の量子化と、行ごとに精度が変わる per-channel を実装し、誤差とメモリの交換を確かめる。
</Summary>

## この章で作るもの

[open-models](/parts/open-models) で見たオープンモデルは重みが公開されているが、Llama 3 70B を fp32 で動かすには 280GB のメモリが要る。コンシューマ GPU の VRAM は 24GB 程度で、そのままでは載らない。量子化はこの壁を崩す。各重みを 32bit の浮動小数から 8bit や 4bit の整数に写せば、メモリは 1/4〜1/8 になり、4bit 量子化した 70B は 35GB 前後まで縮んで現実的な範囲に入る。

原理は素朴だ。連続値である重みを、整数の格子点に丸める。格子の間隔(scale)を決めれば、実数と整数コードは相互に変換できる。[disk-and-pages](/parts/disk-and-pages) でバイト単位のレイアウトを詰めたのと同じ、精度と容量の交換をここでも行う。

<FigureBox caption="対称量子化。max|x| を整数の最大コードに合わせて格子間隔 scale を決め、各値を最寄りの格子点に丸める。復元は code×scale で、丸めた分だけ誤差が出る">

```
実数の重み        -0.8      -0.3   0   0.25        0.8
                   │         │    │    │           │
int8 の格子 ───────┼────┼────┼────┼────┼────┼──────┼──  scale = 0.8/127
(-127〜127)      -127      -48    0   40         127

復元: code × scale。丸めで最大 scale/2 の誤差
メモリ: fp32 4byte → int8 1byte(1/4)
```

</FigureBox>

肝は3つ:

1. **scale を決めて丸めるだけ**: 値の範囲を整数の格子に写す係数 scale を決め、round で最寄りに丸める。誤差は格子間隔の半分以内
2. **対称と非対称**: 0 対称に分布する重みは対称量子化、片側に偏る活性値は非対称量子化が向く
3. **scale の単位で精度が変わる**: テンソル全体で 1 つの scale だと、レンジの大きい行に引っ張られる。行ごとに scale を持つ per-channel が精度を守る

## ① 対称量子化: 丸めの誤差を測る

まず対称量子化。`max|x|` を整数コードの最大値に合わせて scale を決め、各値を丸める:

<<< ../../llm/quant/quant.go#symmetric{go}

テストで固定したのは 2 点だ。まず復元誤差が格子間隔 scale の半分を超えないこと。最近傍に丸めるので、どの値も最寄りの格子点までの距離は半間隔以内に収まる。次に 0 が厳密にコード 0 に写ること。対称量子化は 0 を保存するので、バイアスやゼロ埋めが量子化でずれない。

ビット数と誤差の関係も測れる。8bit は 4bit より誤差が 1 桁小さい。ビットを 1 増やすと格子点が倍になり間隔が半分になるので、誤差はビット数に対して指数的に下がる。メモリはビット数に線形なので、ここに「どこで刻むか」の判断が生まれる。

## ② 非対称量子化: 偏った分布に合わせる

重みは 0 対称に分布しがちだが、活性値(特に [RMSNormとSwiGLU](/parts/rmsnorm-swiglu) の後や ReLU 系の出力)は片側に偏る。0.2〜1.0 のような範囲に対称量子化を使うと、負側のコード域が丸ごと無駄になる。非対称量子化は `[min, max]` を整数域全体に写してこれを避ける:

<<< ../../llm/quant/quant.go#asymmetric{go}

ゼロ点(zero)が加わるのがポイントで、実数の 0 がどのコードに対応するかを覚えておく。復元は `(code − zero) × scale` になる。テストでは偏った分布 [0.2, 1.0] で、非対称が対称より誤差が小さいことを固定した。全コード域を使う分だけ格子が細かくなる。

一般に重みは対称、活性は非対称という使い分けになる。重みは静的に一度量子化すればよい(PTQ、学習後量子化)が、活性は入力ごとに範囲が変わるので実行時に scale を決めるか、代表データで事前に統計を取る(キャリブレーション)必要がある。

## ③ per-channel: scale の単位が精度を決める

行列を量子化するとき、scale を 1 つにするか行ごとにするかで精度が変わる。行によってレンジが桁違いに違う場合、これが効く:

<<< ../../llm/quant/quant.go#perchannel{go}

per-tensor は行列全体で 1 つの scale を使う。すると、あるチャネルの重みが極端に大きい(外れ値)と、その値に合わせて scale が粗くなり、小さいレンジの行の分解能が潰れる。per-channel は行ごとに scale を持つので、各行が自分のレンジをフルに使える。テストでは、微小レンジの行と巨大レンジの行を混ぜた行列で、per-channel が小さい行の誤差を守ることを固定した。

実物の重み量子化はほぼ per-channel(出力チャネルごと)が標準で、さらに 1 行を 64〜128 要素のグループに分けてグループごとに scale を持つ group-wise 量子化まで行う。外れ値 1 つが全体を粗くする問題を、scale の単位を細かくして抑える発想だ。

### 動かす

下のデモは 2 つの見方を用意した。「格子と誤差」は重みの分布を int8 / int4 の格子に丸め、ビット数を変えると格子が粗くなって誤差が増える様子を見る。「メモリ」はモデルサイズとビット数から必要メモリを計算し、fp32 では載らないモデルが 4bit なら手元の GPU に収まる境界を確かめられる。

## 設計の観点

- **PTQ と QAT**: 学習後にかける PTQ(post-training quantization)は手軽だが精度が落ちる。量子化を織り込んで学習する QAT(quantization-aware training)は精度が高いが学習コストがかかる。オープンモデルの配布量子化版はほぼ PTQ
- **外れ値問題**: LLM の活性には稀に極端に大きい値が出て、それが per-tensor の scale を粗くする。LLM.int8() は外れ値だけ fp16 に残す混合精度でこれを回避した。scale を細かくする group-wise も同じ問題への別解
- **メモリと計算は別の得**: 量子化は主にメモリ(と帯域)を節約する。整数のまま積を取れば計算も速くなるが、復元してから fp で計算する実装も多く、その場合の得はメモリ律速の解消に限られる
- **どこまで刻めるか**: int8 はほぼ無損失、int4 で実用、int2/int1 は品質が急落する。誤差はビットに指数的だが、モデルの冗長性が吸収できる下限がある。4bit が実用の主戦場になっている
- **重みと活性の非対称**: 重みは静的で per-channel 対称、活性は動的で per-tensor 非対称、という組み合わせが典型。何が静的で何が動的かが量子化戦略を分ける

## 対照と裏どり

| 手法 | ビット | 単位 | 特徴 |
|---|---|---|---|
| fp16 / bf16 | 16 | — | 学習・推論の標準。fp32 比で半分 |
| LLM.int8() | 8(+外れ値fp16) | per-tensor + 混合 | 外れ値を分離してほぼ無損失の int8 |
| GPTQ | 3〜4 | per-channel + group | 誤差を後続に伝播補正する PTQ |
| AWQ | 4 | per-channel + group | 重要チャネルを保護する PTQ |
| QLoRA | 4(NF4) | group | 4bit 凍結重み + LoRA で微調整 |

裏どり:

- **LLM.int8()(2022)**: [Dettmers et al.](https://arxiv.org/abs/2208.07339)。外れ値特徴量を fp16 に残す混合精度で、8bit のほぼ無損失化を示した
- **GPTQ(2022)**: [Frantar et al.](https://arxiv.org/abs/2210.17323)。二次情報で丸め誤差を補正し、4bit でも高精度を保つ PTQ
- **AWQ(2023)**: [Lin et al.](https://arxiv.org/abs/2306.00978)。活性の大きいチャネルに対応する重みを保護する
- **QLoRA(2023)**: [Dettmers et al.](https://arxiv.org/abs/2305.14314)。4bit 量子化と LoRA(次章)を組み、単一 GPU での大規模モデル微調整を可能にした

## 簡略化したこと

- **round-to-nearest のみ**: GPTQ/AWQ のような誤差補正は実装せず、素朴な最近傍丸め
- **group-wise なし**: 行単位(per-channel)まで。実物の 64〜128 要素グループ分割は本文で言及のみ
- **量子化行列積なし**: int8 のまま積を取る高速化は実装せず、復元して誤差を比較する形に留めた
- **外れ値・混合精度なし**: LLM.int8() の外れ値分離は設計の観点で触れるに留めた
