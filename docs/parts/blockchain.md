# ブロックチェーン

> 実装: [`crypto/blockchain/`](https://github.com/esh2n/sharin/tree/main/crypto/blockchain) / 実行: `go test ./crypto/blockchain/`

<Summary>
ブロックチェーンの正体は「改竄コストを計算量で買う、追記専用のログ」。各ブロックが前のブロックのハッシュを含むので、過去を1つ書き換えると以降が全部壊れる。それを隠すには全部を作り直すしかなく、Proof of Work がその作り直しに莫大な計算を要求する。だから改竄が割に合わない。db 編の「追記だけのログ」と同じ発想を、信頼できる第三者なしで成立させたもの。
</Summary>

## この章で作るもの

ハッシュチェーンに Proof of Work を足したミニ・ブロックチェーンを作る。
暗号通貨の値動きの話ではなく、「**中央の管理者なしに、過去を書き換えられない台帳**」が
どういう仕組みで成り立つのかを見る。

この章の肝は3つ。

- ブロックチェーンは「**改竄コストを計算量で買う、追記専用ログ**」
- 各ブロックが**前のハッシュを含む**から、過去の改竄が連鎖的に露見する
- **Proof of Work** が、改竄を隠すための作り直しを割に合わなくする

## ハッシュチェーン: 過去を固める

各ブロックは、自分の中身に加えて**前のブロックのハッシュ**を持つ。
そして自分のハッシュは「中身 + 前のハッシュ」から計算される。

<FigureBox caption="ハッシュチェーン。各ブロックのハッシュは前のハッシュを含んで計算される。だから鎖のどこか1つを変えると、それ以降のハッシュが芋づる式に変わる">

```
ブロック0        ブロック1              ブロック2
[data: genesis]  [data: alice→bob 10]   [data: bob→carol 5]
[prev: なし  ]   [prev: hash(0) ────]   [prev: hash(1) ────]
[hash: h0    ]   [hash: h1        ]     [hash: h2        ]
      └──────────────┘   └──────────────────┘
```

</FigureBox>

<<< ../../crypto/blockchain/blockchain.go#block{go}

もしブロック1の中身をこっそり「alice→bob 1000000」に書き換えると、ブロック1の
ハッシュ h1 が変わる。するとブロック2が持っている「prev: h1」が古い値のままなので
食い違う。**1つの改竄が、それ以降の鎖を全部壊す**。これがハッシュチェーンの改竄検出。

## でも、全部作り直せばいい?

鋭い疑問。改竄したブロックのハッシュを計算し直し、後続の prevHash も順に直していけば、
辻褄は合ってしまう。ハッシュチェーンだけでは「作り直しのコストがゼロ」だから、
改竄を止められない。

そこで **Proof of Work(PoW)** が要る。

## Proof of Work: 作り直しを高くつかせる

PoW のルールはシンプル: **ブロックのハッシュが、先頭に決められた数の 0 で始まらないと
無効**とする(難易度)。ハッシュは中身を少し変えるだけで予測不能に変わるので、
条件を満たすハッシュを得るには、ブロックに含めた **nonce という数字をひたすら
変えて試す**しかない。

<<< ../../crypto/blockchain/blockchain.go#pow{go}

「先頭が 0 ○個」の確率は指数的に小さいので、難易度が上がるほど、条件を満たす nonce を
見つけるのに膨大な試行(=計算=電気代)が要る。これが**マイニング**。

ここでハッシュチェーンと組み合わさると効いてくる。**過去を1つ改竄して隠すには、
そのブロックと、それ以降の全ブロックを再マイニングしないといけない**。
チェーンが長いほど、難易度が高いほど、その計算量は現実的に不可能なほど積み上がる。
改竄が「割に合わない」。これがブロックチェーンの「改竄コストを計算量で買う」の意味。

**試す**: ブロックを追加してから、過去のブロックの「中身を改竄」を押すと、
そのブロックと後続が赤くなって鎖が壊れる。「再マイニング」で単体は直せるが、
後続はまだ壊れたまま。全部直すには全部を再マイニングするしかない。

## db 編との関係: 追記ログの発展形

この構造、[ログ構造KV](./log-structured-kv)で見た「追記だけのログ」に似ている。
実際、発想は同じだ。**過去を書き換えず、末尾に足していくだけ**。

違いは「誰が正しさを保証するか」。log-structured-kv は1台のサーバが管理していた。
ブロックチェーンは**管理者がいない**。誰でもブロックを足せるし、誰でも検証できる。
その代わり、改竄を防ぐ仕組みを「信頼」ではなく「計算コスト」で担保する。
これが「信頼できる第三者なしの台帳」という発明の核心。

## 取引の署名: 誰の取引か

実物のブロックチェーンでは、ブロックの中身は「取引の集まり」で、各取引には
[crypto 編](./crypto)の**署名**が付く。「alice が bob に10払う」という取引に
alice が秘密鍵で署名するので、alice 本人しかその取引を作れない(他人が
なりすまして alice のコインを動かせない)。

つまりブロックチェーンは、この教科書で作ってきたものの合流点:

- [crypto](./crypto) の**署名**: 取引の本人性(誰のコインか)
- ハッシュチェーン: 過去の改竄検出
- Proof of Work: 改竄を計算コストで防ぐ
- [ログ構造KV](./log-structured-kv) の**追記ログ**: 台帳の形

## メリット / デメリット

**メリット**

- 中央の管理者なしで「過去を書き換えられない台帳」が作れる
- 誰でも検証できる(全ブロックのハッシュと PoW を確認するだけ)
- 単一障害点がない(P2P で全員が台帳のコピーを持つ)

**デメリット**

- **PoW は電力を大量に消費する**(セキュリティを計算=電気で買っているので当然)
- 遅い・スループットが低い(ビットコインは毎秒7取引ほど)
- 51%攻撃(全計算力の過半を握れば改竄できる)。難易度と分散でコストを上げて防ぐ
- 「一度書いたら消せない」は利点にも欠点にもなる

**実例**

- ビットコイン(PoW の元祖)、初期のイーサリアム
- 近年は Proof of Stake(計算でなく資産を賭ける)へ移行する流れ(電力問題ゆえ)
- Git も実はハッシュチェーン(各コミットが親コミットのハッシュを持つ。PoW はない)

## 簡略化したこと

- **P2P・合意なし**: 単一ノード。実物は「最長チェーンが正」で分散合意する
- **取引は文字列1つ**: 実物は署名付き取引の集まり + merkle root で束ねる
- **難易度固定・報酬なし・残高管理なし**: マイニング報酬や UTXO は扱わない
- **SHA-256 は標準ライブラリ**: 自作ハッシュは扱わない
