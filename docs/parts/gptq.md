# 誤差を配る量子化(GPTQ)

> 実装: [`llm/gptq/`](https://github.com/esh2n/sharin/tree/main/llm/gptq) / 実行: `go test ./llm/gptq/`

## この章で作るもの

[量子化](/parts/quantization)の章で、重みを整数の格子点に丸めた。1つずつ独立に丸めて、出た誤差はそのまま捨てる。誤差は格子間隔の半分以内に収まるので、それ以上できることは無いように見える。

だが、何を小さくしたいのかを問い直すと話が変わる。

層の出力は内積になる。`y = Σ wᵢxᵢ` なので、効いてくるのは重み1つずつのずれではなく、**入力を掛けて足し合わせたあとのずれ**だ。個々の丸めが半格子以内でも、同じ向きに揃えば積み上がる。

だったら、丸めて出た誤差を捨てずに、**まだ丸めていない重みへ肩代わりさせればよい**。前から順に1つずつ確定させ、確定するたびに残りを動かす。

肩代わりが効くのは、入力どうしが似た動きをするときになる。入力 3 と入力 7 がいつも一緒に上下しているなら、`w₃` を少し減らして `w₇` を少し増やしても、出力はほとんど変わらない。逆に、まったく無関係に動く入力どうしでは肩代わりできない。

<FigureBox caption="丸めた誤差を捨てるか、残りに配るか。配れば重みそのもののずれは増えるが、出力のずれは減る">

```
  素朴な丸め(誤差を捨てる)

    w₀ ──丸め──▶ ŵ₀    誤差 +0.03  捨てる
    w₁ ──丸め──▶ ŵ₁    誤差 +0.02  捨てる
    w₂ ──丸め──▶ ŵ₂    誤差 +0.04  捨てる
                        ────────────
                        出力には  0.09 ぶん積み上がる


  誤差を配る

    w₀ ──丸め──▶ ŵ₀    誤差 +0.03 ─┐
                                    ├─▶ w₁, w₂ を動かしてから丸める
    w₁'──丸め──▶ ŵ₁    誤差 -0.01 ─┤
    w₂'──丸め──▶ ŵ₂    誤差 -0.01 ─┘
                        ────────────
                        出力には  0.01 ぶんしか残らない

    重みそのものは最寄りの格子点から離れる。それでよい。
    小さくしたいのは重みのずれではなく、出力のずれだから。
```

</FigureBox>

肝は3つ:

1. **小さくしたいのは出力のずれ**: 重みのずれは増やしてよい。増やして出力を守る
2. **配る先と量は入力の相関が決める**: 相関を無視すると配る先が消え、素朴な丸めに戻る
3. **分解1回で全段ぶんが手に入る**: 順に確定させても、なぞるのは1回で済む

## ① 小さくしたいのは出力のずれ

まず、何を測るのかを分ける:

<<< ../../llm/gptq/gptq.go#error{go}

重みそのもののずれと、出力のずれ。素朴な丸めが小さくしているのは前者で、本当に守りたいのは後者になる。

実測がこうなった(64次元、共通成分の強い入力を256回ぶん、3bit):

| | 重みのずれ | 出力のずれ |
|---|---|---|
| 素朴な丸め | **0.08682** | 0.32736 |
| 誤差を配る | 0.09272 | **0.04069** |

**重みのずれは増えているのに、出力のずれは8分の1になっている**。最寄りに丸めるのをやめたのだから、重みが離れるのは当然だ。それを承知で離す。テストで、この2つが逆向きに動くことを固定した。

## ② 配る先と量は入力の相関が決める

誰にどれだけ肩代わりさせられるかは、入力どうしの相関に入っている:

<<< ../../llm/gptq/gptq.go#hessian{go}

`Hessian` が `H = X Xᵀ / n` を作る。`H[i][j]` は入力 `i` と入力 `j` がどれくらい一緒に動くかで、ここが大きいほど肩代わりが効く。

対角に少し下駄を履かせているのは、相関が強すぎると逆行列が立たなくなるからになる。実物も同じことをする。

配る手順そのものは短い:

<<< ../../llm/gptq/gptq.go#quantize{go}

丸めて、出た誤差を対角で割り戻して、まだ確定していない先へ比例配分する。それだけだ。

相関の強さを変えて測ると、得の大きさがそのまま動く:

| 入力の共通成分 | 素朴な丸め | 誤差を配る | 比 |
|---|---|---|---|
| 0.0 | 0.37310 | 0.37350 | 1.00 |
| 0.5 | 0.25517 | 0.18892 | 1.35 |
| 0.7 | 0.27364 | 0.11339 | 2.41 |
| 0.9 | 0.32736 | 0.04069 | **8.05** |
| 0.95 | 0.34461 | 0.02488 | **13.85** |

共通成分が 0、つまり入力がまったく無関係に動く場合は、配っても得が無い(1.00倍)。テストで、この場合に結果がほとんど変わらないこと、そして共通成分を増やすほど得が大きくなることを固定した。

同じことを別の角度からも確かめられる。ヘッセ行列の非対角を落として対角だけにすると、相関を無視したことになる。すると配る先が消えて、**素朴な丸めと1ビットも違わない結果**になる。テストで、全要素が一致することを固定した。

LLM の重み量子化でこの手が効くのは、**活性の次元どうしに強い相関があるから**になる。相関の無いところでは、この工夫は空回りする。

## ③ 分解1回で全段ぶんが手に入る

ここが GPTQ が元の手法(OBQ)から進んだところになる。

理屈だけを追うと、1つ確定させるたびに「残った重みについてのヘッセ行列」を作り直す必要がある。行と列を1つ削った行列の逆行列は、元の逆行列から行と列を削ったものとは違うからだ。素直にやると、重み1つごとに逆行列を取り直すことになる。

<<< ../../llm/gptq/gptq.go#cholesky{go}

`CholeskyUpper` がこれを1回で片づける。`H⁻¹` を `Uᵀ U` に分解しておくと、**上三角 `U` の `i` 行目が、そのまま `i` 段目の配り方になる**。削っていく操作が、分解の中にすでに入っている。

だから、重みを前から1回なぞるだけで済む。逆行列も分解も最初の1回だけで、あとは掛け算と引き算しか出てこない。数万次元の層を現実的な時間で量子化できるのは、これがあるからになる。

順に確定させる形なので、端では性質が変わる。先頭の重みには誰も配っていないので、素朴な丸めとまったく同じところへ行く。テストで固定した。逆に最後の重みは、それまでの全部を受け取ったうえで、配る先が無い。

なお、格子間隔は元の重みから先に決めて動かさない。配ったせいで最大値が変わり格子まで動くと、何と何を比べているのか分からなくなる。

## 設計の観点

- **何を小さくしたいのかを先に決める**: 中間の量を小さくしても、最後に効く量が小さくなるとは限らない
- **中間の精度は譲ってよい**: 重みのずれを増やして出力のずれを減らす。譲れる場所を見つける
- **効く条件を言えるようにする**: 相関が無ければ得が無い。効かない場合を測って示す
- **同じ計算を繰り返さない**: 分解1回に畳み込めるなら、段ごとに解き直さない
- **順に確定させる形は端が特殊になる**: 先頭と末尾の扱いを把握しておく
- **他の工夫と組み合わせる**: 区画ごとの格子や外れ値の分離とは目的が違うので、同時に使える

## 対照と実例

| 手法 | 何を動かすか | 効く条件 | 要るもの |
|---|---|---|---|
| 素朴な丸め | 何も動かさない | 常に | 重みだけ |
| 区画ごとの格子 | 格子の細かさ | 区画の中でレンジが揃う | 重みだけ |
| 外れ値の分離 | 持ち方 | 桁違いの値がごく一部 | 重みだけ |
| 列の引き伸ばし(AWQ) | 格子の配り方 | 効きの偏りがある | 活性の大きさ |
| **誤差を配る(GPTQ)** | **丸め先** | **入力に相関がある** | **入力の相関(ヘッセ行列)** |

裏どり:

- **GPTQ(2022)**: [Frantar et al.](https://arxiv.org/abs/2210.17323)。OBQ を大規模モデルに載せられるところまで速くした。列の順を固定してよいこと、コレスキー分解で段ごとの更新をまとめられることが要点
- **OBQ / OBS**: 元をたどると LeCun らの Optimal Brain Damage、Hassibi らの Optimal Brain Surgeon。**枝刈りのための道具**だったものを、丸め先を選ぶ問題に持ち込んだ形になる
- **キャリブレーションデータ**: ヘッセ行列は実際の入力から作るので、代表的な入力を数百件ほど流す必要がある。重みだけを見る手法との大きな違い
- **damping**: 対角に下駄を履かせないと逆行列が立たない。実装では対角の平均に対する割合(1%程度)を足すのが定番
- **組み合わせ**: 実物の GPTQ は区画ごとの格子と併用する。この章では配ることだけを取り出している

## 簡略化したこと

- **1行だけ**: 実物は行列の全行を同時に処理する。ここでは1本の重みベクトルだけ
- **区画ごとの格子なし**: 格子は全体で1つ。実物は 64〜128 要素ごとに持つ
- **列の並べ替えなし**: 実物は効きの大きい列から先に確定させる選択肢がある
- **段階的な更新なし**: 実物はブロックごとに区切って、まとめて更新する(計算の局所性のため)
- **キャリブレーションが人工的**: 入力は共通成分と揺れから作る。実物は実際の文章を流して集める
- **枝刈りなし**: 同じ枠組みで重みを 0 にする(枝刈り)話は扱わない
