# network/proxy

HTTP リバースプロキシ + ラウンドロビン負荷分散。ネットワーク編の集大成。

## 肝

- リバースプロキシは「クライアントとバックエンドの間に立つ代理人」。受けたリクエストを
  裏のサーバに転送し、応答を返す。1枚挟むだけで負荷分散・SSL終端・キャッシュ等を集約できる
- L4(TCP をそのまま中継)と L7(HTTP を理解して転送・書き換え)の違いが主題。
  この実装は L7 で、リクエストを解釈して X-Forwarded-For を足す
- X-Forwarded-For は「本当のクライアントの IP」をバックエンドに伝えるヘッダ。
  これがないとバックエンドから見た送信元が常にプロキシになる

## 簡略化したこと

- L7 のみ(L4 の生 TCP 中継は章で説明)
- 負荷分散はラウンドロビンのみ(重み・最小接続数・ヘルスチェックなし)
- keep-alive なし。ヘッダ書き換えは XFF の追加だけ(Host 書き換え等は省略)
- リトライ・サーキットブレーカーなし(バックエンド不通は即 502)
