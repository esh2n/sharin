# network/dns

DNS リゾルバの最小実装(A レコード)。ドメイン名 → IP を UDP で引く。

## 肝

- DNS の問い合わせは UDP で送るバイナリメッセージ(HTTP のようなテキストではない)。
  12バイトのヘッダ + 質問 + (応答なら)回答、という固定フォーマット
- ドメイン名は [長さ][ラベル]... の形。応答では名前をポインタで参照する圧縮が使われる
- 問い合わせには ID を付け、応答の ID と照合する。一致しなければ別の問い合わせの応答
- 圧縮すると回答1件が名前の長さによらず 16 バイト固定になる。512 バイトに入る件数は
  55 バイトの名前で 27 件(圧縮なしなら 6 件)。入らなければ TC を立てて TCP へ落ちる

## 測ったこと

| 名前 | 名前のバイト数 | 名前を指す | 名前を書き直す |
|---|---|---|---|
| example.com | 13 | 30 件 | 17 件 |
| www.example.com | 17 | 29 件 | 15 件 |
| d111111abcdef8.cloudfront.net | 31 | 29 件 | 10 件 |
| ec2-203-0-113-25.ap-northeast-1.compute.amazonaws.com | 55 | 27 件 | 6 件 |

## 簡略化したこと

- A レコード(IPv4)のみ。AAAA/CNAME/MX 等は扱わない
- 再帰リゾルバ(8.8.8.8 等)に丸投げ(RD=1)。ルートから辿る反復解決はしない
- キャッシュ・TTL 管理なし。EDNS・TCP フォールバック・DNSSEC なし
- 名前の圧縮は「読み飛ばし」だけ対応(展開して名前を復元はしない)
