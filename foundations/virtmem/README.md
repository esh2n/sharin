# virtmem — 仮想メモリのアドレス変換

各プロセスが「自分だけの連続したメモリ」を持つ錯覚。仮想アドレスをページ番号+オフセットに分け、ページテーブルで物理フレームへ変換する。ページフォルト(デマンドページング)・TLB・プロセス隔離を実装する。

## 肝

- **アドレス分割**: 仮想アドレス = 上位のページ番号 + 下位のオフセット。オフセットは変換で変わらない
- **ページテーブル**: ページ番号 → 物理フレーム番号の対応。MMU がこれを引いて変換する
- **デマンドページング**: 未常駐ページに触るとページフォルト。そこで初めて物理フレームを割り当てる
- **TLB**: 直近の変換を覚える小さなキャッシュ。同じページの再アクセスは一発(TLB ヒット)
- **プロセス隔離**: プロセスごとに別のページテーブル。同じ仮想アドレスでも別の物理フレームを指す
- **segfault / OOM**: アドレス空間外のアクセスは segfault、物理フレーム枯渇は OOM

## 効果の固定(テスト)

- `TestProcessIsolation`: 2 プロセスが同じ仮想アドレスで別々の物理フレームを指す
- `TestDemandPagingFault`: 初回アクセスでフォルト、2 回目は常駐でフォルトなし
- `TestTLBHits`: 同じページの再アクセスが TLB ヒット、Flush で再び miss

## 使い方

```go
fa := virtmem.NewFrameAllocator(16) // 物理メモリ(全プロセス共有)
m := virtmem.New(256, fa)           // pageSize=256 の MMU(1プロセス)
m.Map(0, 4)                         // ページ 0..3 をアドレス空間に
paddr, err := m.Translate(0x0140)   // 仮想 → 物理(初回はフォルトで割り当て)
m.FlushTLB()                        // 文脈切替時
```

## 簡略化したこと

- **単段ページテーブル**: 実物は多段(x86-64 は 4 段)で、巨大なアドレス空間を疎に表す
- **TLB は無限**: 実物は数十〜千エントリの固定サイズ。追い出しがある
- **スワップなし**: フレーム枯渇時にディスクへ退避(ページアウト)せず OOM にする
- **権限・ダーティビットなし**: 読み書き実行の保護や書き換え検出は扱わない
