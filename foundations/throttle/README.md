# foundations/throttle

CPU スロットリング(cgroup v2 の `cpu.max`)の最小実装。

## 肝

- メモリの上限は「超えたら断る」で済むが、CPU は断れない。時間は流れ続けるので、
  できるのは「次の期間まで走らせない」だけになる
- `cpu.max` は "quota period" の固定窓。期間の頭で使える量が戻り、使い残しは消える。
  つまり**貯まらない**ので、平均で足りていても止まる
- 同時に走らせる本数を増やすと、枠は同じでも**消えるのが早くなる**。走る時間が期間の頭に固まる
- `cpu.max.burst` は使い残しの繰り越し。暇のあとの一時的な集中を吸える

## 測ったこと

`cpu.max = 40 / 100`。合計 80 tick ぶんの仕事を 8 本に分けて同時に出す:

| 同時に走らせる本数 | 最後の1本 | 枠を使い切った時刻 | 止まって過ごす割合 |
|---|---|---|---|
| 1 | 140 tick | 40 tick 目 | 60% |
| 2 | 120 tick | 20 tick 目 | 80% |
| 8 | 105 tick | 5 tick 目 | 95% |

60 tick ぶんの仕事は、平均では足りているのに 120 tick かかる(60 tick 止められる)。

3期間暇にしたあと 100 tick の仕事を出すと、繰り越しなしで 220 tick / 繰り越しありで 100 tick。

## 簡略化したこと

- tick が単位(実物はナノ秒)。仕事は途中で止めて再開できる前提
- weight(枠に余裕があるときの分け合い方)なし。cgroup の階層なし
- I/O 待ちなし。走らせる順は配列の順そのまま
