# bytecode — バイトコードコンパイラとスタックマシン

ソースコードを**バイトコードにコンパイルし、スタックマシンで実行する**——
lang 編のツリーウォーク評価の「次の段」を Go でモデル化する。ランタイム内部編の
パーツ。字句・構文解析は [`foundations/lang`](../lang) をそのまま再利用し、
評価器の代わりに**コンパイラ + VM** を載せる。同じ言語を別の実行方式で走らせる
対比が主題だ。

教科書の章: [bytecode](https://sharin-2a1.pages.dev/parts/bytecode)

## これは何か

lang 編のインタプリタは、実行のたびに AST(木)を再帰的にたどり直す
(ツリーウォーク)。単純で正しいが、同じ木を何度も歩き回るのは遅い。ほとんどの
本番言語はもう一段挟む——木を一度**平らな命令列(バイトコード)**にコンパイルし、
それを**仮想マシン(VM)**が回す。

```
  ソース                AST(木)              バイトコード(平らな命令列)
  "1 + 2"   ──lang──▶   (+ 1 2)   ──compile──▶  OpConstant 0   ┐
                                                 OpConstant 1   ├─ VM が上から実行
                                                 OpAdd          │  (スタックで計算)
                                                 OpPop          ┘
```

VM 側の仕事は単純なループになる——命令を1つ取り出し(fetch)、種類を見て(decode)、
実行する(execute)。木を歩くより、この一直線のバイト列を舐めるほうが速い。
CPython(`ceval.c`)・Ruby(YARV)・Java(JVM バイトコード)・WebAssembly は、
みなこの「コンパイル → VM」の形をしている。

## 肝は3つ

1. **バイトコード = 平らな命令列 + 定数プール**: 木を、オペコード(1 バイト)と
   オペランドが隙間なく詰まった 1 本のバイト列に落とす。整数などの値は命令に
   埋めず、定数プールに置いて番号で指す
2. **スタックマシン**: レジスタを持たず、オペランドは全てスタックで受け渡す。
   `OpAdd` は「上位2つを pop して足し、結果を push」——ただそれだけ。式の評価が
   push/pop の列に化ける
3. **制御フロー = 条件ジャンプ**: `if` は `OpJumpNotTruthy` / `OpJump` に変換される。
   飛び先はコンパイル時にはまだ分からないので、仮の値で出しておき後から書き換える
   (**back-patching**)。木の分岐が、平らな命令列上のジャンプになる

## ファイル

- `code.go` — 命令セット(`Opcode`)、命令の符号化 `Make` と逆アセンブル。
  `OperandWidths` でオペコードごとのオペランド幅を定義
- `compiler.go` — `Compiler`。lang の AST を一度歩いて命令列 + 定数プールへ。
  シンボルテーブルで変数名 → グローバル番号を管理。if の back-patching もここ
- `vm.go` — `VM`。スタックマシンの fetch-decode-execute ループ。`Run(src)` は
  lang の字句・構文解析を再利用し、コンパイル → 実行まで一気通貫する入口

## 設計メモ

- **`<` は `>` へ読み替える**: `a < b` を「`b > a`」としてコンパイルし、`OpGreater`
  だけで両方賄う。オペコードを1つ減らすコンパイラの定番テク
- **真偽値と null は共有インスタンス**: `True`/`False`/`Null` を使い回すので、真偽値の
  等値比較はポインタ一致で済む
- **式文の後始末**: 式だけの文の後に `OpPop` を入れ、スタックを次の文のために空へ
  戻す。プログラム末尾に残る「最後に pop された値」が実行結果
- **フロントエンドは lang を再利用**: 同じ字句・構文解析器から、評価器(lang)にも
  コンパイラ(本章)にも進める——「木をどう実行するか」だけが違う

## 簡略化したこと

- **関数・クロージャは範囲外**: 呼び出しには**フレーム**(戻り先・ローカル領域)と
  コール規約が要る。本章は式・`let`・`if` までに絞り、関数は明示的にコンパイルエラーで
  弾く(仕組みは章で説明)。lang 編はツリーウォークでクロージャまで実装済み
- **整数と真偽値のみ**: 文字列・配列・ハッシュ・組み込み関数は無し
- **グローバル変数のみ**: `let` は全てグローバル領域に置く。ローカル変数(フレーム内)は
  関数と一緒に省略
- **最適化なし**: 定数畳み込み・ピープホール最適化・レジスタ割り当てはしない。
  素直な命令列をそのまま出す
- **JIT なし**: バイトコードは解釈実行のみ。機械語への JIT コンパイルは次の段(章で言及)
