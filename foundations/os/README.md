# os — 最小カーネルと協調スケジューラ

OS のいちばん奥にある仕事——「誰が CPU を握るかを決める」——を Go でモデル化する。
計算機の土台編の3つ目のパーツ。実スレッドや割り込み(タイマ)を使わず、
**協調スケジューラ**の仕組みを純粋なデータ構造で決定的に再現する。

教科書の章: [os](https://sharin-2a1.pages.dev/parts/os)

## これは何か

CPU は 1 つ。走れるタスクは同時に 1 つだけ。それを何本ものタスクで分け合うのが
スケジューラの仕事だ。分け方には2つの流派がある。

- **協調(cooperative)**: タスクが**自発的に** `yield` / `sleep` して CPU を手放す。
  スケジューラはその瞬間にだけ次のタスクを選ぶ。横取り(プリエンプション)はしない
- **プリエンプティブ(preemptive)**: タイマ割り込みで OS が**強制的に**取り上げる。
  タスクの都合と無関係に切り替わる

ここで作るのは前者。初期の Mac OS(〜9)や Windows 3.x が採っていた方式であり、
いまの async/await・コルーチン・goroutine の「協調ポイントで切り替わる」感覚の原型でもある。

```
        ┌──────────────── Kernel(論理時計 + スケジューラ)──────────────┐
        │                                                              │
        │   run queue(FIFO = round-robin)      blocked(sleep 中)      │
        │   [ B ][ C ]  ← 末尾へ戻す              { A: wake@6 }         │
        │     ↑ 先頭を dispatch                                        │
        │   ┌ Running: A ┐                                             │
        │   │ pc=3       │  ← 保存される文脈の実体は pc だけ            │
        │   │ Run/Yield/ │     context switch = pc の保存と復元         │
        │   │ Sleep …    │                                             │
        │   └────────────┘                                             │
        └──────────────────────────────────────────────────────────────┘
```

## 肝は3つ

1. **文脈(コンテキスト)= pc**: タスクの状態は「プログラムのどこまで実行したか」に
   尽きる。実機はレジスタやスタックを退避するが、本質は同じで、context switch とは
   保存された位置(pc)を戻して続きから走らせることにすぎない
2. **協調 = 横取りしない**: `Run(n)` は n tick 走りっぱなしで、その間 CPU を手放さない。
   だから `yield` を書かない貪欲なタスクは、他を丸ごと待たせる。これが協調方式の弱点で、
   タイマ割り込みによるプリエンプションが生まれた理由でもある
3. **ブロックと空転(idle)**: `sleep` したタスクは run queue から外れ、起床時刻まで
   戻らない。実行可能タスクが尽きて sleeper だけ残ると、CPU は次の起床時刻まで
   空転(idle)して時計を進める——実機の HLT(なにもせず待つ)に当たる

## ファイル

- `task.go` — `State`(ready/running/blocked/done)、命令 `Op`(`Run`/`Yield`/`Sleep`)、
  `Task`(プログラム `[]Op` と文脈 `pc`)
- `scheduler.go` — `Kernel`(論理時計・run queue・blocked)。`Spawn` / `Step` / `Run` と、
  起床 `wake`・空転 idle・トレース記録

## 設計メモ

- **round-robin**: run queue は素朴な FIFO。dispatch は先頭から取り、yield したタスクは
  末尾へ戻す。これだけで、みなが `yield` する限り CPU は公平に回る
- **決定的**: 乱数もタイマも使わない。同時に起きる sleeper は「起床時刻 → 生成順」で
  並べるので、同じ入力なら常に同じスケジュールになる(テストとデモが安定する)
- **時計は CPU を使ったときだけ進む**: `Run(n)` で n、idle で「次の起床まで」進む。
  sleep はこの論理時計に対する相対指定

## 簡略化したこと

- **プリエンプションは無し**: タイマ割り込みで強制的に切り替える方式は扱わない
  (協調方式との対比として章で説明する)
- **スケジューリング方針は round-robin のみ**: 優先度・多段フィードバックキュー・
  CFS のような公平配分は省略
- **1 コア固定**: マルチコア/負荷分散は扱わない。走れるのは常に 1 タスク
- **同期プリミティブは sleep のみ**: mutex・セマフォ・チャネル待ちなどのブロック要因は
  タイマ(sleep)1 種類に単純化。「ブロックして起こされる」骨格は同じ
- **実行は模擬**: タスクは `Run`/`Yield`/`Sleep` の並びで、実際の計算はしない
