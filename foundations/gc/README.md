# gc — mark-sweep ガベージコレクタ

「もう要らないメモリを、誰がどうやって見つけて返すのか」を Go でモデル化する。
ランタイム内部編の1つ目のパーツ。実メモリや unsafe は使わず、ヒープを
**オブジェクトの有向グラフ**として決定的にモデル化し、**tricolor マーキング**で
到達集合を求めて、辿れなかったものを回収する。

教科書の章: [gc](https://sharin-2a1.pages.dev/parts/gc)

## これは何か

GC が答える問いはただ1つ——「このオブジェクトはもう要らないか?」。判定基準は
**到達可能性(reachability)**だ。

- **ルート**: スタックのローカル変数やグローバルから「直接」指されているオブジェクト
- **生きている** = ルートから参照をたどって到達できる
- **ゴミ(garbage)** = どのルートからも到達できない → 回収してよい

だから GC は「グラフの到達可能性判定」に尽きる。ルートから幅優先/深さ優先で辿り、
辿れたものに印(mark)を付け、印の付かなかったものを掃く(sweep)。

```
        roots(スタック/グローバル)
          │
          ▼
        ┌───┐     ┌───┐     ┌───┐
        │ A │────▶│ B │────▶│ C │     ← 到達可能 = 生存(mark)
        └───┘     └───┘     └───┘
                      ▲──────────┘(循環していても到達可能なら生存)

        ┌───┐     ┌───┐              ┌───┐
        │ E │◀───▶│ F │              │ G │   ← どのルートからも辿れない = garbage(sweep)
        └───┘     └───┘              └───┘
```

## 肝は3つ

1. **到達可能性 = 生死**: 参照カウント(何本指されているか)ではなく、「ルートから
   辿れるか」で決める。だから **E ↔ F のような循環参照も回収できる**——参照カウント方式が
   リークする典型ケースを、mark-sweep は正しく掃ける
2. **tricolor マーキング**: white(未到達)/ gray(到達したが子は未走査)/ black(走査済み)の
   3色。ルートを gray にして始め、gray を1つ取り出して black にし、その子の white を gray に
   する——を繰り返す。gray が尽きたら到達集合が確定する
3. **不変条件「black → white を直接指さない」**: マークの各手でこれを保つ。これは
   並行・インクリメンタル GC(プログラムを止めずに GC する)の理論的な土台でもある

## ファイル

- `object.go` — `color`(tricolor)と `Object`(ID・名前・参照先 ID の一覧)
- `heap.go` — `Heap`(オブジェクト集合 + ルート集合)。Alloc / PointTo / Unpoint / AddRoot 等
- `collect.go` — `Collection`(1回の mark-sweep)。`Start` → `MarkStep`(1手ずつ)→ `Sweep`、
  および一気に走らせる `Collect`

## 設計メモ

- **グラフとしてのヒープ**: オブジェクトは ID を持ち、参照は「相手の ID」で表す。ポインタの
  代わりに ID を使うことで、実メモリ無しに到達可能性だけを純粋に扱える
- **ダングリング参照は生じない**: 生存オブジェクトが回収対象を指すことは起こり得ない——
  指していれば、その相手はマーク中に gray になり生存側に入るからだ
- **1手ずつ観察できる**: `MarkStep` で tricolor の広がりを刻めるので、GC の内部が
  そのまま見える(教科書のデモがこれを可視化する)

## 簡略化したこと

- **stop-the-world 前提**: マーク中にプログラムが参照を書き換えない、と仮定する。実機の
  並行 GC は write barrier で不変条件を守るが、本章はそこまで踏み込まない
- **mark-sweep のみ**: コピー GC・世代別 GC・参照カウント(との対比のみ言及)は実装しない
- **メモリ断片化・確保器は無し**: sweep は「回収した」と印を消すだけ。free list や
  コンパクションは扱わない
- **オブジェクトの大きさは扱わない**: 個数で数える。バイト単位の会計はしない
