# wasm — 最小 WebAssembly インタプリタ

**実際の `.wasm` バイナリをパースし、スタックマシンで実行する**——WebAssembly の
最小サブセットを Go で実装する。ランタイム内部編のパーツ。[bytecode 編](../bytecode)で
作った自前バイトコード VM の「実物・標準化版」が WASM だ。

教科書の章: [wasm](https://sharin-2a1.pages.dev/parts/wasm)

## これは何か

bytecode 編では、自分で決めた命令セットを自分の VM で回した。WebAssembly は、
それを**業界標準にした移植可能なスタックマシンのバイトコード**だ。ブラウザ・
サーバ・エッジ・プラグイン基盤で動く。bytecode 編との違いは3つ:

1. **実在するバイナリ形式をパースする**: 先頭のマジック `\0asm` + バージョン、その後に
   型・関数・エクスポート・コードといった**セクション**が並ぶ。数値は **LEB128**(可変長整数)で
   詰められている。ここでは実際にこのバイト列を読む
2. **型付きの値**: WASM の値は型を持つ(i32/i64/f32/f64)。ここでは **i32 のみ**に絞る
3. **構造化制御フロー**: これが最重要。任意アドレスへ `goto` する命令は無く、
   `block` / `loop` / `if` という入れ子ブロックと、その**深さ**を狙う `br`(脱出/継続)しかない。
   だから飛び先は静的に決まり、**検証**(安全性の担保)ができる——サンドボックス実行の土台

## 肝は3つ

1. **バイナリをそのまま読む**: LEB128 で長さやインデックスを読み、セクションを順に解釈する。
   `.wasm` は人間には読めないが、規則は単純
2. **スタックマシン**: bytecode 編と同じく、値スタックで演算する。`i32.add` は上位2つを
   pop して push。ローカル変数は番号でアクセスする
3. **構造化制御フローと br**: `br L` は「今いるブロックの L 個外側」を狙う。**block/if を
   狙えば end の先へ脱出、loop を狙えば本体先頭へ継続**(=ループが回る)。飛び先が構造で
   決まるので、任意ジャンプのような検証不能性が無い

## ファイル

- `leb.go` — LEB128(可変長整数)の読み取り。符号なし/符号つき。バイナリ形式の土台
- `module.go` — オペコード定義、型(`FuncType`)・関数(`Func`)・モジュール(`Module`)・
  デコード済み命令(`Instr`)の表現
- `parser.go` — `Parse([]byte) (*Module, error)`。マジック検査 → セクション読取 →
  関数本体を命令列へデコードし、`block`/`loop`/`if` を対応する `end`/`else` に結びつける
- `interp.go` — `Invoke` / `Run`。値スタック + 制御スタックで、構造化制御フローを実行する

## 設計メモ

- **飛び先はコンパイル時に確定**: パース時に各 `block`/`loop`/`if` の `end`(と `else`)の位置を
  求めておく。実行時の `br` はその表を引くだけ——WASM の検証器が事前に安全性を確かめられるのと同じ発想
- **loop と block の違いが継続と脱出**: `br` が `loop` を狙うと本体先頭へ戻り(繰り返し)、
  `block`/`if` を狙うと `end` の先へ抜ける(脱出)。同じ `br` 命令が、狙うブロックの種類で意味を変える
- **関数呼び出しは Go の再帰**: `call` は呼び先を `execFunc` で実行し、結果をスタックへ。
  再帰(自分自身の `call`)もそのまま動く。深さガードで暴走を止める
- **テストは実バイナリを組んで食わせる**: テスト側に小さな `.wasm` エンコーダを置き、
  `add` / `max` / ループの `sum_to` / 再帰の `fact` を実バイト列にして、実パーサ+VM で検証する

## 簡略化したこと

- **i32 のみ**: i64 / f32 / f64、型変換命令は扱わない。値型の検査は「i32 か」だけ
- **線形メモリなし**: WASM の目玉である線形メモリ(`memory` + `i32.load`/`i32.store` +
  境界チェックによるサンドボックス)は実装しない。命令は値スタックとローカルで完結する範囲に限定
- **import/global/table なし**: ホスト関数のインポート、グローバル変数、間接呼び出し
  (`call_indirect`)・テーブルは扱わない
- **ブロック結果型は void 扱い**: `block`/`loop`/`if` が値を返す形は使わず、結果はローカルと
  関数戻り値でやり取りする(`block (result i32)` は省略)
- **検証はしない**: 実機の WASM は実行前に型・スタック整合を静的検証する。ここでは信頼できる
  入力を前提に実行のみ(検証の「なぜ可能か」= 構造化制御フローは本文で説明)
