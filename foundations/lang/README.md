# lang — 小さなプログラミング言語

ソース文字列を字句解析 → 構文解析 → 評価して実行する、小さな言語をフルスクラッチする。
計算機の土台編の最初のパーツ。Thorsten Ball の *Writing an Interpreter in Go*(Monkey言語)の
コアを、日本語コメントで再構成したもの。

教科書の章: [lang](https://sharin-2a1.pages.dev/parts/lang)

## これは何か

`5 + 3 * 2` や `let add = fn(a, b) { a + b }; add(2, 3)` のようなプログラムを解釈して
値にする。3段のパイプライン:

```
ソース文字列 ──字句解析──▶ トークン列 ──構文解析──▶ AST ──評価──▶ 値
              (lexer)                 (Pratt parser)      (tree-walk)
```

- **字句解析** (`lexer.go`): 文字列を1文字ずつ舐めてトークン(`let`, `5`, `+`, `(` …)に切る
- **構文解析** (`parser.go`): Pratt 解析でトークン列を AST に。演算子の優先順位を正しく組む
- **評価** (`eval.go`): AST を根から再帰的にたどり、実行時の値(`object.go`)へ畳み込む

`Run(src string) Object` が入口。字句→構文→評価を通し、結果の値かエラーを返す。

## 対応する言語機能

- 整数と真偽値、算術(`+ - * /`)・比較(`< > == !=`)・前置(`- !`)
- `let x = ...;` の束縛、`return`
- `if (cond) { ... } else { ... }`(**式**——値を返す)
- `fn(params) { body }` の第一級関数、呼び出し、**クロージャ**
- 実行時エラー(型不一致・未定義変数・ゼロ除算・引数の数違いなど)

## 肝は3つ

1. **3段に分ける**: 字句(文字→トークン)・構文(トークン→木)・評価(木→値)。各段は前段の出力だけを入力に取るので、単体で理解・テストできる
2. **Pratt 解析で優先順位**: トークンごとに前置/中置の解析関数を登録し、優先順位表で結合を決める。`a + b * c` が `a + (b * c)` に正しく組める
3. **クロージャ = 環境の抱え込み**: 関数値が「定義時の環境」を抱える。呼び出しごとに、その環境を外側にした内側環境を作って引数を束縛する。だから返された関数が外側の変数を覚えている

## 設計メモ

- **式指向**: `if` も `fn` も値を返す式。だから `let x = if (c) { 1 } else { 2 };` が書ける
- **`return` は包んで持ち上げる**: `ReturnValue` でくるみ、ブロックを突き抜けて関数の外まで持ち上げる。剥がすのは関数境界とトップだけ
- **エラーも値として持ち上がる**: `Error` オブジェクトを返し、各所で `isError` を見て評価を止める。例外機構は使わない
- **AST の `Boolean` と実行時の `BooleanObj` は別物**: 構文上の `true`(木)と、実行して得た真偽値(値)を区別する

## 簡略化したこと

- **整数と真偽値だけ**: 文字列・配列・ハッシュ・浮動小数は無し(Monkey本の後半)
- **ツリーウォーク評価**: バイトコード + VM ではなく、AST を直接歩く最も素直な方式。速くはない
- **エラーは最初の1件**: 構文エラーは複数あっても先頭だけ返す。行番号・位置情報は持たない
- **ガベージコレクタなし**: Go の GC に乗る。メモリ管理は [gc 編](../../PLAN.md)で別途扱う
- **組み込み関数・標準ライブラリなし**: `len` や `print` の類は無し
