# foundations/oom

OOM killer の最小実装。

## 肝

- メモリが足りないときの素直な答えは「断る」だが、Linux は既定で断らない。
  予約の合計が物理を超えても通す(オーバーコミット)
- 帳尻は実際にページを触った時点で合わせる。足りなければ誰かを殺す。
  **「断る」を「あとで殺す」に取り替えた**という言い方ができる
- 殺す相手は `oom_score`(抱えている量が物理に占める割合 + `oom_score_adj`)で選ぶ。
  「誰のせいか」ではなく「殺してどれだけ空くか」なので、**足りなくした本人とは限らない**
- `oom_score_adj = -1000` は完全な免除。守ると、代わりに小さい相手が死ぬので空く量が減る

## 測ったこと

物理 1000 に 4 つが 400 ずつ申し込む:

| | 結果 | 殺した数 |
|---|---|---|
| 申し込みを断る | 3 つめで断られた | 0 |
| 断らず、あとで殺す | 4 つとも通った。予約 1600(1.6 倍) | 触ると発生 |

800 抱えている相手が居るところに、小さいプロセスが触りに来たとき:

| | 殺した数 | 空いた量 | 要求は通ったか |
|---|---|---|---|
| 本人を殺す | 1 | 100 | 通らない(本人が死んだ) |
| 効く相手を殺す | 1 | 800 | 通る |

`oom_score_adj = -1000` で db を守ると、殺されるのは web に変わり、空く量は 600 → 300。

## 簡略化したこと

- ページ単位でなく量だけで数える。共有メモリ・スワップなし
- 殺す前の回収(キャッシュ破棄・スワップアウト)を試みない
- cgroup の階層なし。殺す順の細かい規則なし
