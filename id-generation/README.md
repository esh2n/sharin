# id-generation

## 肝

- どの方式も材料は「時刻・乱数・ノードID」の3つで、配合が違うだけ
- 時刻を上位ビットに置くと辞書順=時刻順になり、B-Tree インデックスの挿入が
  右端に集中して速くなる(ソート可能性の価値)
- 乱数で衝突を「確率的に無視」するか(UUID系)、ノードID+連番で「構造的に排除」するか
  (Snowflake)が設計の分かれ目。後者は時計の巻き戻りが敵になる

## 簡略化したこと

- UUIDv7 の同一ミリ秒内単調性オプション(rand_a を連番に使う)は未実装
- ULID のデコード(文字列から時刻を復元)は未実装
- Snowflake の連番枯渇は「次のミリ秒まで待つ」のではなくエラーにしている
