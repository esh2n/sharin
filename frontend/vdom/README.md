# vdom — 仮想DOM + diff/patch

宣言的UIの心臓部を最小構成でフルスクラッチする。フロント編の最初のパーツで、
このリポジトリで初めて Go でなく **TypeScript** で書くパーツ。

教科書の章: [仮想DOM](https://sharin-2a1.pages.dev/parts/vdom)

## これは何か

「毎回あるべき画面の全体像（仮想DOMの木）を作り、前回の木との**差分だけ**を
実DOMに当てる」——React などが内部でやっていることの核だけを取り出したもの。

- `h(type, props, ...children)` — 仮想DOMノードを組み立てる（JSX が変換される先）
- `mount(vnode)` — 仮想DOM木から実DOMを作る（初回描画）
- `diff(oldTree, newTree)` — 2つの木を比べ、実ノードに当てる**パッチ関数**を返す

## 肝は3つ

1. **宣言的UI = 差分**: 手続き的に「ここのテキストを書き換えて…」と DOM をいじる代わりに、
   「今あるべき木」を毎回まるごと宣言する。差分の算出はライブラリ側の仕事
2. **diff/patch**: 2つの木を再帰的に突き合わせる。種類が違えば差し替え、同じタグなら
   props と子だけを再帰的に差分。テキストは内容が違っても `nodeValue` をその場更新
3. **`diff` は純粋関数**: 実DOMを触るのは返ってきたパッチを当てる瞬間だけ。
   「差分の計算」と「実DOMの変更」を分けると、木の比較をテストしやすく理解しやすい

## 設計メモ

- **パッチ関数方式**: `diff(old, new)` は `(node) => node` というパッチ関数を返す。
  比較の段階では実DOMを一切触らないので、差分ロジックが純粋で追いやすい
- **子の突き合わせは index ベース**: 同じ位置どうしを比べる素朴な方式。
  共通範囲は再帰 diff、余りは末尾追加/末尾削除。**key による並べ替え検出は入れていない**
  （下記「簡略化したこと」）
- **テキストはその場更新**: テキストノードは内容が変わっても作り直さず `nodeValue` を書く。
  これが「最小のDOM操作」の一例

## 簡略化したこと

- **key 付き差分なし**: リストの並べ替え・挿入を最小手数で扱う keyed reconciliation は未実装。
  index ベースなので、先頭挿入は「以降全部が別物」と見なされ余分に作り直す
- **コンポーネント・状態管理なし**: 関数コンポーネント/フック/再レンダリングのスケジューリングは無し。
  ここは vdom（描画エンジン）だけ。状態→再描画のループは次章以降
- **属性の特別扱いは最小**: `class`/`style`/`value` 等のプロパティ vs 属性の使い分け、
  SVG 名前空間などは扱わない。`on*` のイベントと通常属性のみ
- **フラグメント・ポータルなし**

## 動かす

```bash
cd frontend
pnpm install
pnpm test        # vitest（happy-dom 環境）
pnpm cov         # カバレッジ付き
pnpm typecheck   # tsc --noEmit（strict）
```
