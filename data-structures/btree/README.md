# data-structures/btree

## 肝

- B-Tree の存在理由はディスク。1ノード = 1ページに大量のキーを詰めて枝分かれを太くし、
  「ページ読み回数 = 木の高さ」を数段に抑える
- 挿入は降りながら満杯ノードを先に割る(proactive split)。木が高くなるのは root が割れる瞬間だけ
- 昇順キーは常に右端ノードに入る(挿入の局所性)。id-generation 編の
  「UUIDv7 がインデックスに優しい」の実体

## 簡略化したこと

- 削除は未実装(隣接ノードからの借用・併合が入り、挿入よりだいぶ複雑)
- メモリ内のみ。実物のページI/O・バッファプールはない
- B+Tree ではない(実物のRDBは値をリーフに集め、リーフを連結して範囲走査する)
- 並行制御(ラッチ)なし
